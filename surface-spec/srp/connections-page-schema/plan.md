## Migration plan
Not an Alembic migration and not part of the closed SQL stream, and with no `docs/ETL-Enhancements.md` entry (the local-schema stance, ruled 2026-10-27).
- **File:** `surface-api/srp/db/local/connections_schema.sql`; `if not exists` throughout; one `begin ... commit`; runs after the Home, SRS, Profile, Insights and Web analytics scripts. It alters no existing table.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run; the seed's `--backup-to` covers the old values and rows it changes afterwards (`web_checks`, `srs_lane_gaps`).
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as the owner role `anandhu`.
- **Verify:** catalog query (one new table, constraints, indexes, grants, no RLS, every other table's columns unchanged); after the seed, JOIN counts: every seated seat has 11 rows, the social count equals the SRS lane count, LinkedIn is connected where the Profile cites it, the Indexing source follows Search Console.
- **Rollback:** a commented block at the end: `drop table if exists srp_cleanup.connected_accounts;`; the schema-only backup is the second fallback and the seed backup restores the corrected values.

## Risks
- **The seed changes existing mock rows** (`web_checks` Indexing source and tier; the `connections` row of `srs_lane_gaps`). They are mock and backed up, and a test pins exactly which rows and columns move; the Web analytics, SRS and seed tests that compared the old text are updated.
- **LinkedIn connected for every seat** (C10) makes that card constant across seats; the variety is in the other accounts. If a ruling later says a Profile fact may come from LinkedIn by import, C10 relaxes and the Profile sources would need their own correction.
- **SRS lane texts:** the lane's earned points are not touched, only its "you" count text; the SRS read's notes that quote the count are checked by the existing SRS tests.
- **Size of `connections.tsx`** (259 lines of literals): a literal missed leaves a sample value on a real page; the render tests list the constants that must not appear and the trace checks the rest.
- **Sample parity:** the sample page must stay byte for byte the same, including the `4 + connected` count and the Connect clicks' first render; the old-versus-new markup comparison and the existing tests guard it.
- **Mock rules** (the Zillow and Yelp match states, which accounts a seat has) are unruled; merge stays blocked on the rulings in the spec's canon review; local use is fine.
- **Gates:** tasks 2 and 4 change the database and do not start without your go-ahead (an auto-mode permission block on a seed run happened last time: if it happens again I stop and give you the command to run); a failed run rolls back and backups are taken first.

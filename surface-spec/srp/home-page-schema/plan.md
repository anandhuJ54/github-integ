## Migration plan
This is **not** an Alembic migration and not part of the closed SQL stream (spec Data, same stance as the sign-in increment: `srp_cleanup` is a local schema, no change-log entry).
- **File:** `surface-api/srp/db/local/home_schema.sql` (a new folder, separate from `db/migrations/`); `if not exists` throughout; one `begin ... commit`.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run. The new tables are empty until the seed, whose own backup (`--backup-to`) covers them afterwards. No existing table is changed, so there is no `zz_backup_*` table.
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as the owner role `anandhu` (the API's `v3_app` cannot create in the schema).
- **Verify:** catalog query: the 17 `home_*` tables; the other 81 tables' columns identical to a snapshot taken before; constraints, indexes and grants counts; no RLS; then JOIN counts after the seed (every seated active user joined to a state, snapshots, 49 cells, a leader).
- **Rollback:** `drop table` of the 17 `home_*` tables (they have no dependants outside the set), listed in a commented block at the end of the script; the schema-only backup is the second fallback. Nothing outside `home_*` is dropped.

## Risks
- **Size of the UI refactor.** `home-day1.tsx` (1,574 lines), `home-day7.tsx` (736) and `shell.tsx` (2,793) hold many literals. A literal missed leaves a sample number on a real page; the render tests list the constants that must not appear and the trace checks the rest. Each of tasks 10, 11 and 12 can exceed ~400 changed lines; if so it is split by section before starting.
- **Sample parity.** The sample view must stay byte for byte the same; the parity test and the existing render tests guard it. The sample model must reproduce today's contradictions (128 vs 130 reviews, baselines 298 vs 384) exactly, since it is only for the sample.
- **A new table rule for tests.** The integration fixtures copy tables with `LIKE ... INCLUDING ALL`, which drops foreign keys; the new fixtures run the real script instead, and need `tier_agents` to exist in the scratch schema first.
- **Seed size.** About 40 seats x (3 snapshots x (10 lanes + 49 cells) + other rows) is roughly 8,000 rows; the seed and its tests stay fast, but the backup file grows (JSON lines, outside the repo).
- **Clock-dependent day.** `day.n` is computed from the server clock, so a seat's layout changes as days pass unless the seed is re-run with a new `--as-of`; tests pin the clock.
- **Mock scorer.** The 850-point mock score and bands are not SRS v5 and not ruled; the page says mock. Merge stays blocked on the open rulings listed in the spec (scoring and identity ownership, band thresholds, plan and trial rule, `srp_cleanup` name, O1, O5); local use is fine.
- **Gates.** Tasks 2 and 5 change the database; they do not start without your go-ahead. A failed run rolls back (one transaction), and the backups are taken first.

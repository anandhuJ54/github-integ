## Extend-never-duplicate check
Checked 2026-10-27, read-only, against the live `v3_local` catalog and the repo:
- **Live:** no relation matches visibility, engine, spot, leader or competitor position (the query above returned none); `home_competitors` has the constraints `pk`, `fk_tier_agent_id`, `ck_score`, `uq_seat_position` and no `(id, tier_agent_id)` unique yet.
- **Repo:** no file outside this increment names an `insights_*` table.
- **Nearest existing structures and why they are not extended:** `google_analytics` (polymorphic resource key, mostly empty, no profile-views column), `ai_authority_stats` (one row per agent, no engine split), `home_snapshots.ai_cited/ai_checked` (kept; the engine rows split it and must add up), `home_competitors` (rivals; extended only by the composite unique), `home_map_cells` (ranks; the leaders reference it).
- **Reused:** `home.parse_ids`, `owner_of`, `_iso`, `rankColor`, the seed's guards, `_sync`, backup, `--as-of`, scratch-schema fixtures, the contract generator, the `profile-model.ts` / `profile-page.tsx` patterns.
- **No new** route family, role system, outbox, entitlement table or price constant; SRS v5 and `public` are untouched.

## Migration plan
Not an Alembic migration and not part of the closed SQL stream (same stance as the Home, SRS and Profile scripts: `srp_cleanup` is a local schema).
- **File:** `surface-api/srp/db/local/insights_schema.sql`; `if not exists` throughout (the constraint guarded by a catalog check); one `begin ... commit`; runs after the Home, SRS and Profile scripts.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run; the seed's `--backup-to` covers rows afterwards.
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as owner role `anandhu`.
- **Verify:** catalog query (four tables, constraints, indexes, grants, no RLS, the one new constraint, every other column unchanged); after the seed, JOIN counts: every seated seat has 6 (or fewer by design) visibility rows, 3 engine rows summing to Home's AI figures, one position per rival, 147 leader rows.
- **Rollback:** a commented block at the end: drop the four tables, then `alter table home_competitors drop constraint`; the schema-only backup is the second fallback.

## Risks
- **Spot-leader volume** (about 7,200 rows for the ~49 seats if 147 each; check actual seat count): small, but the seed must stay one transaction and idempotent; the integration test covers the second run.
- **Alter on `home_competitors`:** the composite unique is additive and cannot fail on existing rows (ids are already unique); a catalog diff and row-count check prove nothing else moved.
- **Consistency with Home** (engine sums, map, rating) is by seed and test, not a trigger (N6): a later Home reseed would break the sums; the integration test and a note in the seed order (Insights after Home) guard it.
- **Size of `insights.tsx`** (561 lines of literals): a literal missed leaves a sample figure on a real page; the render tests list the constants that must not appear and the trace checks the rest.
- **Sample parity:** the sample page must stay byte for byte the same; the old-versus-new markup comparison guards it.
- **Mock rules** (average-position convention, tiers, plan gating, note wording) are unruled; merge stays blocked on the rulings in the spec's canon review; local use is fine.
- **Gates:** tasks 2 and 4 change the database and do not start without your go-ahead; a failed run rolls back and backups are taken first.

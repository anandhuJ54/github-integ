## Migration plan
Not an Alembic migration and not part of the closed SQL stream, and with no `docs/ETL-Enhancements.md` entry (the local-schema stance, ruled 2026-10-27).
- **File:** `surface-api/srp/db/local/network_schema.sql`; `if not exists` throughout; one `begin ... commit`; runs after the Home, SRS, Profile, Insights, Web analytics and Connections scripts. It alters no existing table. `network_referrals` references `network_partners`, so the partners table is created first.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run; the seed's `--backup-to` covers the rows it changes afterwards (the two new tables are empty before the first run).
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as the owner role `anandhu`.
- **Verify:** catalog query (two new tables, constraints, indexes, grants, no RLS, every other table's columns unchanged); after the seed, JOIN counts: no Zillow reason without a matched Zillow, no closing claim without a connected Loan system, every named partner is a promoted partner of the same seat, at most 8 promoted per seat, dates in range, and the legacy tables' row counts unchanged.
- **Rollback:** a commented block at the end: drop `network_referrals`, then `network_partners`; the schema-only backup is the second fallback.

## Risks
- **The screen is 913 lines of constants and local state** (partner transitions, the referral tab, nudges, sheets): a literal missed leaves a sample value on a real page; the render tests list the constants that must not appear and the trace checks the rest. The local `net` state is keyed by partner id, so real ids (database ids) must stay strings in that map.
- **Sample parity:** the sample page must stay byte for byte the same on both tabs, including the counters, "N of 8" and the sentences that change after clicks; the old-versus-new markup comparison and the existing tests guard it.
- **Referral link rows:** `network_referrals.partner_id` is a foreign key to a table the seed rewrites in place; `_sync` keeps the lowest id per key, so partners must keep their ids across runs (tested: a second run changes 0 rows ids included) and referral partner ids are resolved by partner name and seat, never by position.
- **Mock rules** (what a request, a suggestion, a received or a given referral is, the status vocabulary, "New · I texted them a welcome", the 120-day window, the layout-driven counts) are unruled; merge stays blocked on the rulings in the spec's canon review; local use is fine.
- **Closings and Zillow rules shrink the variety:** only 13 seats have the Loan system connected and 21 have Zillow matched, so most seats show closing-free text; the seed tests assert that both kinds occur.
- **Gates:** tasks 2 and 4 change the database and do not start without your go-ahead (an auto-mode permission block on a seed run happened earlier: if it happens again I stop and give you the command to run); a failed run rolls back and backups are taken first.

## Migration plan
Not an Alembic migration and not part of the closed SQL stream (same stance as `home_schema.sql` and `srs_schema.sql`: `srp_cleanup` is a local schema, no change-log entry).
- **File:** `surface-api/srp/db/local/profile_schema.sql`; `if not exists` throughout; one `begin ... commit`; runs after the Home and SRS scripts.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run; the seed's `--backup-to` covers the new rows and the old `tier_agents` column values afterwards.
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as the owner role `anandhu`.
- **Verify:** catalog query (two new tables, constraints, indexes, grants, no RLS, every other table's columns unchanged); after the seed, JOIN counts: every seated active user joined to its fact rows and 6 graph rows, no table-backed field holds a value, the corrected `tier_agents` columns hold no "Mock tier agents" junk for seeded seats.
- **Rollback:** a commented block at the end of the script: `drop table if exists` for the two tables; nothing else is dropped. The schema-only backup is the second fallback, and the seed backup restores the old `tier_agents` values.

## Risks
- **The seed overwrites mock columns of an existing table** (`tier_agents.title`, `description`, phones, photo). They are mock and backed up first, and the Home and SRS pages read some of them (title through the persona, year started); a test and the backup make the change reversible. The seat read for other pages keeps working (it reads the same columns).
- **Size of `profile.tsx`** (1,262 lines of literals, the edit sheets and voice flow): a literal missed leaves a sample fact on a real page; the render tests list the constants that must not appear and the trace checks the rest. Task 9 may exceed ~400 changed lines; if so it is split by card before starting.
- **Sample parity:** the sample page must stay byte for byte the same; the old-versus-new markup comparison and the existing tests guard it.
- **Local edit store:** the edit overlay applies on top of database facts; a stored edit for a fact that later changes in the database would hide the new value until reset. Accepted for a demo-only store; the per-seat key stops cross-person leaks.
- **Mock rules:** the thin-bio threshold, the label-to-tier mapping, and the graph counts are mock and unruled; merge stays blocked on the rulings in the spec's canon review; local use is fine.
- **Gates:** tasks 2 and 4 change the database and do not start without your go-ahead; a failed run rolls back (one transaction) and backups are taken first.

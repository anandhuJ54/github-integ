## Migration plan
Not an Alembic migration and not part of the closed SQL stream, and with no `docs/ETL-Enhancements.md` entry (the local-schema stance, ruled 2026-10-27).
- **File:** `surface-api/srp/db/local/web_analytics_schema.sql`; `if not exists` throughout; one `begin ... commit`; runs after the Home, SRS, Profile and Insights scripts. It alters no existing table.
- **Backup:** `pg_dump --schema-only --schema=srp_cleanup v3_local` to a private file outside the repo (mode 600) before the run; the seed's `--backup-to` covers the old values and rows it changes afterwards (`website_analytics_data`, `srs_lane_gaps`, `home_next_moves`).
- **Apply:** only on `v3_local`, only after your go-ahead (task 2), as the owner role `anandhu`.
- **Verify:** catalog query (one new table, constraints, indexes, grants, no RLS, every other table's columns unchanged); after the seed, JOIN counts: every seated seat has 10 checks, the scored sum equals its lane, `total_score` equals its lane, and the SRS gap text and the
  Home move subtitle agree with the markup row.
- **Rollback:** a commented block at the end: `drop table if exists srp_cleanup.web_checks;`; the schema-only backup is the second fallback and the seed backup restores the three corrected values.

## Risks
- **The seed changes existing mock rows** (`website_analytics_data.total_score`, the `website` rows of `srs_lane_gaps` and `home_next_moves`). They are mock and backed up, and a test pins exactly which rows and columns move; the SRS and Home read tests that
  asserted the old texts are updated. Home's other rows and the lane points are not touched.
- **Feasibility of the split** (nap 20 or 30, the rest within 72): true on the live data today; a seat where it is not makes the seed stop with a plain message instead of writing a contradiction (a test with an impossible lane). **Found in task 3:** it holds for the 40 seeded seats but not for every seat id (in a 60-seat set, seat 50 has a full lane and no address), so seeding more seats can stop the seed until a ruling decides which side gives way (the Profile address, or the lane). Recorded, not worked around.
- **Home plan alignment order:** the Home plan is built first, the Profile plan second, the web plan third, and the aligned Home plan is the one applied; a test pins that an unaligned plan is never written.
- **Size of `website.tsx`** (685 lines of literals, the scan timer and the hand-off): a literal missed leaves a sample value on a real page; the render tests list the constants that must not appear and the trace checks the rest. Task 9 may exceed ~400 changed lines; if so it
  is split by card before starting.
- **Sample parity:** the sample page must stay byte for byte the same, including its timers' first render; the old-versus-new markup comparison and the existing tests guard it.
- **Mock rules** (the 42/30/20/10 split, the readiness thresholds, the content thresholds, the web-vitals use) are unruled; merge stays blocked on the rulings in the spec's canon review; local use is fine.
- **Gates:** tasks 2 and 4 change the database and do not start without your go-ahead; a failed run rolls back (one transaction) and backups are taken first.
